# DanceFlow for Unity

[DanceFlow ecosystem](https://kieransimkin.co.uk/danceflow/) · [Source](https://github.com/kieransimkin/DanceFlow.Unity)

Check the exact UPM package.json, source commit, samples and release state. The audited 0.5.0-preview.1 source is not a stable release. Pin a reviewed commit when installing through Unity Package Manager; Unity 6000.0+ is required.

Reuse StemLab source-verified beat timelines and canonical DanceRudiments recording/rig-profile/rig-motion contracts. Keep DSP/manual song time, 16 ticks per beat, 64 integer pips per beat, original recording clocks and explicit excerpt mappings distinct. Verify source bytes, profile hashes, finite bounds and reviewed skeleton/bone mappings. Captures never loop automatically.

Select the relevant opt-in sample: ClockPhaseCube, ShaderClockURP, SongReactiveLandscape or RiggedCharacterDemos. Synthetic 120-BPM robots demonstrate a contract, not real-character rigging, song matching, licensed asset rights or GPU acceptance. Preserve URP/graphics requirements, material bindings and explicit root/blend policy.

Run the canonical managed clock, recording and rigging checks plus Python fixture/showcase checks. Record actual Unity Editor, PlayMode, GPU/framebuffer, WebGL/licence and real-character evidence independently. No Unity runtime, editor launcher, heavyweight audio, external FBX or model weights ship in the DanceFlow toolkit. Read danceflow://workflows/potbot-unity for composition and host limits.
